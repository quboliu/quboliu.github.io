# 博客双语排版规范

## 参照与阅读方式

采用 DDIA V2 双语全校版的语义单元排版，参照工程为工作区的
`mindbuffer/books/ddia-v2/ddia-v2-typest-dual/`，依据 `template.typ` 中的
`dual`、`dual-heading`、`dual-caption`、`dual-note`、`dual-footnote`，以及
`references/layout-decisions.md`。网页版沿用其阅读关系；B5 页幅、书页页眉、
强制分页和纸本脚注的字号补偿不搬入网页。

- 英文在前，中文紧随其后。按完整段落、完整列表、示例或论证块配对；一组可以包含多个段落。
- 两种语言均为正文：同字号、同颜色、同行距、同段间距。字体可分别使用拉丁衬线体与中文宋体。
- 正文使用连续单栏。在桌面与手机上都保持相同顺序；不用左右双栏、折叠译文、逐句标签或译文卡片区分语言。
- 中文不缩小、不变灰、不缩进成引用块。正文两种语言只以字形区别；正文中的链接、加粗等语义样式正常保留。
- 网页正文宽度上限 48rem，默认行高约 1.72；正文左对齐，不复制纸本的强制两端对齐。
- 标题使用直立无衬线字形，深蓝作为浅色主题的结构强调色；深色主题采用足够清晰的浅蓝。

## 正文源格式

文章 frontmatter 设置 `bilingual: true`。只有实际存在配对译文的文章使用该标记，
不凭 `paper-translation`、`docs-translation` 或 `repost` 分类自动推断。

```markdown
<div class="bilingual-unit">

<div lang="en">

A complete English paragraph or semantic unit.

</div>

<div lang="zh-CN">

完整的中文段落或语义单元。

</div>

</div>
```

HTML 容器与 Markdown 内容之间留空行，容器结束与下一段、列表、表格、代码围栏
之间也留空行。否则 Markdown 可能把下一段或代码围栏吞入 HTML 块。
不要把正文重写为 HTML 字符串；保留 Markdown 的链接、图片管线、列表、数学与代码处理。

## 标题、图注与附属内容

- **标题**：新标题写作 `## English heading｜中文标题`，渲染成一个标题中的英文行与中文行。只有一个标题层级、目录项与锚点，不为译文再建一个标题。页面 H1 同样配对，转载或论文等栏目标签可以单独作为较小的标题前缀。
- **旧标题锚点**：原来只有英文标题、后接引用式中文标题的文章，可保留英文标题并在后面写 `<!-- bilingual-heading: 中文标题 -->`；共享渲染器将译文并入同一标题，保留原英文锚点。迁移时实际核对原有链接与目录。英文目录链接可增加空锚点别名，但不能更换原锚点或增加目录项。
- **图注**：图片只出现一次，原文图注与译文紧随图片，英文在前、中文在后；使用 `bilingual-unit bilingual-caption` 容器。已有 `Figure …｜图 …` 图注由共享渲染器分成两个语言行。两种语言采用相同的图注字号与颜色，且均为直立字形。
- **表格**：保留原始单元格、数值和列名。双语列名可保留在同一张表；原文与译文分为两张表时放在同一个语义单元内。不复制数值表只为重复语言标签。普通表格按可用宽度换行；多于四列的表在窄屏按原行展开，各单元格显示真实列名；多层表头需展开 colspan、rowspan 并保留完整的分组列名。
- **代码**：代码本身保留原字符，只展示一次，除非源文已有独立的翻译示例。允许窄屏视觉折行；复制结果必须保持原代码。不翻译标识符或改动程序以配合排版。
- **数学**：不改公式、符号或上下标；数学标记中的星号、下划线不参与中文强调替换。长公式在局部区域横向滚动，不能撑宽页面或缩小正文；仅实际溢出的公式区域进入键盘焦点序列。
- **真实引语**：`blockquote` 用于引用语义。双语引语把一个 `bilingual-unit` 放入同一个引用容器；不要给中文再嵌套第二层引用。所有引用块及其子元素直立。
- **来源说明与译注**：分别使用 `aside.source-note` 与 `aside.translator-note`，可以采用淡底色与蓝色边线。明确区分补充说明与源文正文，不把一般译文放入这些容器。源文双语 Note 的两种语言放入同一个注释容器。
- **脚注**：同一源文注释只有一个定义与编号，定义内依次放英文和中文，使用双语容器；两种语言都链接到该定义。Markdown 脚注中的所有续行按脚注缩进规则处理。网页脚注两种语言同字号，中文直立。
- **嵌套列表**：保留层级、编号及对应的英文说明。列表项中的译文可以使用 `div.list-translation[lang="zh-CN"]`；检查十位数编号的续行缩进，避免译文掉出列表或变成代码。
- **评论与回复**：逐条按原回复树配对，保留作者、日期与互动数据。不要先排整片英文评论，再排整片中文评论；不要把作者信息误认作评论的英文正文。

## 直立字形与强调

中文正文、图注、脚注、引用与行内强调一律直立。中文强调使用 `**加粗**` 或改写；
不使用 `*中文*`、`_中文_`、`<em>`、`<i>` 或 italic 类。英文原文中的真实斜体可保留，
引用块内仍服从全部直立的站点约定。混排段落按文字所属语言标记，避免英文继承中文字形规则。

## 发布验证

1. 同步两站的 `src/styles/bilingual.css`、字体与主题 token、`rehypeBilingual`、标题组件、frontmatter schema 和内容检查器。
2. 两站分别运行 `npm run content:check`、`node --test scripts/bilingual-format.test.mjs` 和 `npm run build`。
3. 批量迁移按迁移前的 Git 版本核对代码、公式、表格单元格、图片、链接与脚注定义；发现旧源格式本身有误时单独说明，不能把格式修复造成的差异归为内容丢失。
4. 实际预览至少覆盖 320px、390px、桌面、深色模式与 130% 字号。检查双语正文视觉权重、中文与引用块字形、标题及目录锚点、脚注回链、图片加载、表格与代码的可读范围。
5. 双语改造不改变两站的内容归属、draft 状态、原发布日期和 URL，也不自动授权把草稿发布到正式站。
